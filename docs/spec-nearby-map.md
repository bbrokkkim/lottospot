## 1. 기능 개요 및 목적

### 개요

"내 주변 판매점 지도"는 사용자의 현재 위치 또는 검색한 주소를 기준으로, 반경 내 로또 판매점을 카카오맵 위에 시각화하는 핵심 기능이다. 단순 위치 안내를 넘어, 명당 스코어(당첨 이력 기반)를 마커에 반영하여 헤비유저가 "가까우면서도 잘 당첨되는 판매점"을 즉시 파악할 수 있도록 한다.

### 목적

- 주 1회 이상 로또를 구매하는 헤비유저가 현재 위치에서 가장 빠르게 명당을 찾을 수 있도록 한다.
- 판매점 위치, 명당 등급, 당첨 이력을 한 화면에서 확인하여 이동 결정까지의 시간을 최소화한다.
- 지도 기반 UI로 공간적 맥락(거리, 방향)을 직관적으로 전달한다.

### 핵심 가치 제안

> "지금 내 주변에서 가장 가까운 명당을 3초 안에 찾는다."

## 2. 사용자 시나리오 (User Story)

### Persona

- 이름: 직장인 김민준 (38세)
- 패턴: 매주 토요일 퇴근 전 로또 1장 구매
- 니즈: 새로운 동네에 있을 때도 명당을 빠르게 찾고 싶다
- 불편함: 포털 지도에서 "로또 판매점" 검색 시 당첨 이력을 알 수 없다

### User Stories

| ID | As a | I want to | So that |
|----|------|-----------|---------|
| US-01 | 헤비유저 | 앱 실행 시 내 현재 위치가 자동으로 지도에 표시되기를 | 별도 입력 없이 바로 주변 판매점을 볼 수 있다 |
| US-02 | 헤비유저 | 반경 내 판매점이 지도 마커로 표시되기를 | 한눈에 가까운 판매점 위치를 파악할 수 있다 |
| US-03 | 헤비유저 | 명당 판매점이 일반 판매점과 시각적으로 구분되기를 | 명당을 우선적으로 선택할 수 있다 |
| US-04 | 헤비유저 | 마커 클릭 시 판매점 상세 정보(당첨 횟수 등)를 볼 수 있기를 | 방문 전 당첨 이력을 확인할 수 있다 |
| US-05 | 헤비유저 | 주소 또는 판매점명으로 검색할 수 있기를 | 특정 지역이나 아는 가게를 바로 찾을 수 있다 |
| US-06 | 헤비유저 | 반경 필터를 조정할 수 있기를 | 넓은/좁은 범위로 유연하게 탐색할 수 있다 |
| US-07 | 헤비유저 | 위치 권한 거부 시에도 주소 검색으로 이용할 수 있기를 | 위치 권한 없이도 서비스를 사용할 수 있다 |

### 4.1 현재 위치 탐지

#### 기능명: GPS 기반 현재 위치 자동 탐지

```
## 현재 위치 탐지
- 목적: 사용자의 현재 위치를 WGS84 좌표로 획득하여 지도 초기 중심점으로 설정
- 트리거: 홈(지도) 탭 최초 진입 또는 "현재 위치" 버튼 클릭
- 입력: 브라우저 Geolocation API (위도, 경도, 정확도)
- 처리:
    1. navigator.geolocation.getCurrentPosition() 호출
    2. 성공 시 반환된 좌표를 지도 중심점으로 설정
    3. 해당 좌표로 /api/stores/nearby 요청 자동 실행
    4. 마지막 성공 좌표를 localStorage에 저장 (재방문 시 재사용)
- 출력: 지도가 현재 위치 중심으로 이동, 내 위치 마커(파란 점) 표시
- 예외 케이스:
    - 위치 권한 거부: 토스트 메시지 "위치 권한이 필요합니다. 주소로 검색해주세요" 표시, 서울 중심부(37.5665, 126.9780) 기본값으로 지도 표시
    - GPS 오류/타임아웃(5초): "위치를 찾을 수 없습니다" 토스트, 마지막 저장 좌표 사용. 없으면 기본값 사용
    - 정확도 500m 초과: 약정확도 경고 표시 없이 정상 처리 (정확도 표시 UI 미제공, 추후 논의)
```

### 4.2 주변 판매점 조회 (반경 필터)

#### 기능명: 반경 기반 판매점 목록 조회

```
## 주변 판매점 조회
- 목적: 지정된 중심 좌표와 반경 내 로또 판매점을 명당 스코어/거리 정보와 함께 조회
- 트리거:
    - 위치 탐지 완료 시 자동 호출
    - 반경 필터 변경 시
    - 검색 결과로 지도 중심이 이동될 때
    - 지도 드래그 후 중심 좌표 변경 시 (디바운스 500ms 적용)
- 입력:
    - lat: 중심 위도 (WGS84)
    - lng: 중심 경도 (WGS84)
    - radius: 반경 (미터 단위, 500 / 1000 / 2000 / 3000 중 선택, 기본값 1000)
    - limit: 최대 결과 수 (기본값 20, 최대 50)
    - sort: 정렬 기준 (distance | score, 기본값 distance)
- 처리:
    1. MySQL ST_Distance_Sphere(좌표, POINT(lng, lat))로 반경 내 판매점 필터링
    2. 영업 상태가 "폐업"인 판매점 제외
    3. 명당 스코어 계산: (1등당첨횟수 × 10) + (2등당첨횟수 × 3) + 최근성보정
       * 가정: 최근성 보정 = 최근 2년 이내 당첨 이력 보유 시 스코어 × 1.5 적용
       * 최근성 보정 기준은 backend-builder와 협의 필요
    4. 거리 오름차순 또는 스코어 내림차순 정렬
    5. Redis 캐시 확인 (키: nearby:{lat_2dp}:{lng_2dp}:{radius}:{sort}, TTL 5분)
- 출력: 판매점 목록 (id, name, address, lat, lng, distance, score, grade, firstWinCount, secondWinCount, recentWinRound)
- 예외 케이스:
    - 반경 내 판매점 0건: "이 근처에 판매점이 없습니다. 반경을 넓혀보세요" 안내
    - 좌표 유효범위 이탈 (한국 영역 외): 400 에러 반환, "유효하지 않은 위치입니다" 토스트
    - DB 조회 오류: 500 에러, "잠시 후 다시 시도해주세요" 토스트
```

### 4.3 지도 마커 표시 (일반/명당 구분)

#### 기능명: 명당 등급별 마커 렌더링

```
## 지도 마커 표시
- 목적: 판매점을 명당 등급에 따라 시각적으로 구분하여 지도에 표시
- 트리거: /api/stores/nearby 응답 수신 완료 시
- 입력: 판매점 목록 (lat, lng, grade, name)
- 처리:
    1. 기존 마커 전체 제거 (지도 갱신 시 중복 방지)
    2. 각 판매점에 등급별 커스텀 마커 이미지 적용 (섹션 3.3 마커 디자인 규칙 참고)
    3. 마커 20개 초과 시 줌 레벨에 따라 클러스터링 적용
       * 가정: 카카오맵 MarkerClusterer 사용. 줌 레벨 4 이하에서 클러스터링 활성화
    4. 내 위치 마커(파란 원형)는 별도 레이어로 항상 최상위 표시
    5. 반경 표시 원 (Circle 오버레이)을 지도에 함께 렌더링
- 출력: 카카오맵 위에 등급별 커스텀 마커 + 반경 원 표시
- 예외 케이스:
    - 동일 좌표에 복수 판매점 존재 시: 가장 높은 등급 마커 우선 표시, 클릭 시 목록 형태로 표시
    - 마커 이미지 로딩 실패 시: 기본 카카오맵 마커로 폴백(fallback) 처리
```

### 4.4 마커 클릭 시 판매점 상세 정보

#### 기능명: 판매점 상세 바텀시트

```
## 마커 클릭 상세 정보
- 목적: 판매점 마커 클릭 시 당첨 이력, 거리, 영업 정보를 즉시 제공하여 방문 결정을 돕는다
- 트리거: 지도 마커 클릭 또는 하단 판매점 카드 탭
- 입력: 판매점 ID
- 처리:
    1. /api/stores/{id} 호출
    2. 바텀시트 슬라이드업 애니메이션 (200ms)
    3. 지도 중심점을 해당 판매점 좌표로 이동
    4. 해당 마커 선택 상태 강조 (마커 크기 1.3배 확대)
    5. 상세 데이터 Redis 캐시 확인 (키: store:detail:{id}, TTL 10분)
- 출력: 바텀시트에 판매점 상세 정보 표시
    - 판매점명, 주소, 거리
    - 명당 스코어, 명당 등급 뱃지
    - 1등 당첨 횟수, 2등 당첨 횟수
    - 최근 당첨 회차 및 날짜
    - 영업 상태 (운영 중 / 정보 없음)
    - 길찾기 버튼 (카카오맵 앱/웹 딥링크)
- 예외 케이스:
    - 상세 API 호출 실패: 이미 목록에서 받은 기본 정보(name, address, winCount)만 표시, 나머지는 "-"
    - 당첨 이력 0건: "당첨 이력 없음" 문구 표시, 스코어 0으로 표시
    - 길찾기 버튼: 카카오맵 앱 미설치 시 카카오맵 웹으로 폴백
```

### 4.5 검색 기능 (주소/판매점명)

#### 기능명: 텍스트 검색

```
## 검색 기능
- 목적: 주소 또는 판매점명 키워드로 원하는 지역/가게를 빠르게 찾아 지도 이동
- 트리거: 검색창 입력 후 엔터 또는 검색 버튼 클릭
- 입력: query (문자열, 2자 이상)
- 처리:
    1. 입력 길이 2자 미만 시 검색 불가, "2자 이상 입력해주세요" 안내
    2. /api/stores/search?query={keyword} 호출
    3. 백엔드에서 판매점명 LIKE 검색 + 카카오 로컬 API 주소 검색 병행
       * 가정: 주소 검색은 카카오 로컬 API를 백엔드 프록시로 호출
    4. 결과가 단일 판매점: 해당 판매점 마커로 지도 이동 + 상세 바텀시트 자동 오픈
    5. 결과가 복수: 지도를 전체 결과가 보이도록 fitBounds 처리, 하단 목록 패널 갱신
    6. 결과가 주소 기반: 해당 주소 좌표를 새 중심점으로 설정, 주변 판매점 재조회
    7. 입력 300ms 디바운스 후 자동완성 제안 (판매점명 최대 5건)
- 출력: 검색 결과에 맞게 지도 뷰 이동 + 마커/목록 갱신
- 예외 케이스:
    - 검색 결과 0건: "검색 결과가 없습니다" 표시, 현재 지도 상태 유지
    - 특수문자 입력: 서버 전달 전 프론트에서 sanitize 처리
    - 네트워크 오류: "검색에 실패했습니다. 다시 시도해주세요" 토스트
```

## 6. 데이터 모델

### 6.1 Store (판매점)

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 판매점 고유 ID |
| name | VARCHAR(100) | NOT NULL | 판매점명 |
| address | VARCHAR(255) | NOT NULL | 도로명 주소 |
| address_detail | VARCHAR(100) | NULL | 상세 주소 |
| lat | DECIMAL(10,7) | NOT NULL | 위도 (WGS84) |
| lng | DECIMAL(10,7) | NOT NULL | 경도 (WGS84) |
| location | POINT | NOT NULL, SRID 4326 | 공간 인덱스용 좌표 (ST_Distance_Sphere 활용) |
| phone | VARCHAR(20) | NULL | 전화번호 |
| is_open | TINYINT(1) | NULL | 영업 상태 (1=운영, 0=폐업, NULL=정보없음) |
| created_at | DATETIME | NOT NULL | 최초 등록일 |
| updated_at | DATETIME | NOT NULL | 최종 수정일 |

- 인덱스: location 컬럼에 SPATIAL INDEX 적용 필수
- 가정: 폐업 판매점(is_open=0)은 API 응답에서 제외, DB에는 이력 보존

### 6.2 WinHistory (당첨 이력)

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 이력 ID |
| store_id | BIGINT | FK(store.id), NOT NULL | 판매점 ID |
| round | INT | NOT NULL | 당첨 회차 |
| rank | TINYINT | NOT NULL | 당첨 등수 (1 또는 2) |
| win_date | DATE | NOT NULL | 당첨 발표일 |
| created_at | DATETIME | NOT NULL | 적재일 |

- 인덱스: (store_id, rank, win_date) 복합 인덱스 — 판매점별 등수/기간 조회 최적화
- 유니크 제약: (store_id, round, rank)

### 6.3 명당 스코어 계산 규칙

```
score = (first_win_count × 10) + (second_win_count × 3) + recency_bonus

recency_bonus 계산:
  - base_score = (first_win_count × 10) + (second_win_count × 3) 로 먼저 산출
  - 최근 2년(기준일 기준) 이내 1등 당첨 이력 1건 이상 존재 시: base_score × 0.5 추가
  - 즉, recency_bonus = base_score × 0.5 (조건 충족 시), 0 (미충족 시)

grade 기준:
  - GOLD:   score >= 70
  - SILVER: score >= 40 and score < 70
  - BRONZE: score >= 10 and score < 40
  - NORMAL: score < 10

가정: 최근성 보정 기준(2년, 0.5배)은 backend-builder와 최종 협의 필요.
      스코어는 크롤러 실행 후 배치로 재계산하거나 조회 시 동적 계산 여부도 협의 필요.
```

## 7. 비기능 요건

### 7.1 성능 목표

| 항목 | 목표 | 비고 |
|------|------|------|
| /api/stores/nearby 응답 시간 | 500ms 이내 (P95) | 캐시 히트 시 50ms 이내 |
| /api/stores/{id} 응답 시간 | 200ms 이내 (P95) | 캐시 히트 시 30ms 이내 |
| 지도 마커 렌더링 (20개 기준) | 300ms 이내 | 카카오맵 SDK 렌더링 포함 |
| 동시 접속 처리 | 100 RPS 이상 | 초기 목표 |

### 7.2 캐싱 전략

| 캐시 대상 | 키 패턴 | TTL | 무효화 조건 |
|-----------|---------|-----|------------|
| 주변 판매점 목록 | nearby:{lat_2dp}:{lng_2dp}:{radius}:{sort} | 5분 | 크롤러 신규 데이터 적재 시 전체 무효화 |
| 판매점 상세 | store:detail:{id} | 10분 | 해당 판매점 데이터 변경 시 |
| 검색 결과 | search:{query_hash} | 3분 | 없음 (자연 만료) |

- lat/lng는 소수점 2자리로 반올림하여 캐시 키 생성 (약 1.1km 단위 격자)
- Redis String 타입, JSON 직렬화 저장
- 캐시 미스 시 DB 조회 후 캐시에 저장 (Cache-Aside 패턴)
- 가정: 크롤러 실행은 주 1회 배치, 실행 완료 시 nearby:* 패턴으로 Redis 전체 삭제

### 7.3 공간 인덱스

- Store.location 컬럼에 MySQL SPATIAL INDEX 적용
- ST_Distance_Sphere 쿼리에서 MBR(Minimum Bounding Rectangle) 프리필터링 적용하여 풀스캔 방지
- 가정: 전국 판매점 약 6,000 ~ 7,000개 기준 설계

### 7.4 보안

- 좌표 입력값 서버 측 유효범위 검증 필수 (한국 영역 lat: 33~38.9, lng: 124~132)
- API Rate Limit: IP당 분당 60회 (추후 nginx 또는 Spring 레이어 구현, backend-builder 협의)
- 카카오맵 SDK API 키는 허용 도메인 제한 설정 필수 (프론트 키 노출 최소화)

## 8. 예외 처리 및 엣지 케이스

### 8.1 위치 권한 시나리오

| 상황 | 처리 방법 |
|------|-----------|
| 위치 권한 최초 요청 중 | 지도 위에 "위치 확인 중..." 로딩 스피너 표시 |
| 위치 권한 거부 | 서울 중심 기본 좌표 사용, 검색창 자동 포커스, 안내 토스트 |
| 위치 권한 허용 후 GPS 오류 | 마지막 저장 좌표 사용, 없으면 기본값 |
| 이동 중 위치 갱신 | 자동 추적 없음 (배터리 고려), "내 위치" 버튼 수동 갱신만 지원 |

### 8.2 데이터 이상 케이스

| 상황 | 처리 방법 |
|------|-----------|
| 좌표가 0,0인 판매점 | 크롤러에서 필터링, DB 저장 불가 (NOT NULL + CHECK 제약 권장) |
| 동일 좌표 복수 판매점 | 마커 클릭 시 해당 위치의 판매점 목록 표시 (스택 마커) |
| 스코어가 음수인 경우 | 발생 불가 (횟수는 0 이상), 방어 코드로 max(score, 0) 처리 |
| 미래 날짜의 당첨 이력 | 크롤러에서 유효성 검증, 백엔드 저장 시 현재일 이후 날짜 reject |
| 판매점명에 특수문자 포함 | 그대로 표시 (필터링 없음), 검색 시 이스케이프 처리 |

### 8.3 네트워크/서버 케이스

| 상황 | 사용자 피드백 | 내부 처리 |
|------|-------------|-----------|
| /api/stores/nearby 타임아웃 (3초 초과) | "판매점 정보를 불러오지 못했습니다. 다시 시도해주세요" 토스트 + 재시도 버튼 | 프론트 타임아웃 3초 설정 |
| 500 서버 오류 | "서비스에 일시적인 문제가 발생했습니다" 토스트 | 서버 에러 로그 기록 |
| 카카오맵 SDK 로드 실패 | "지도를 불러올 수 없습니다. 새로고침 해주세요" 전체 화면 안내 | CDN 이슈 대비 재시도 로직 |
| 검색 API 오류 | "검색에 실패했습니다" 토스트, 기존 지도 상태 유지 | 에러 로그 기록 |

### 8.4 UX 엣지 케이스

| 상황 | 처리 방법 |
|------|-----------|
| 반경 내 판매점 50개 초과 | limit=50 제한 적용, "주변에 판매점이 많습니다. 반경을 줄이거나 명당순으로 정렬해보세요" 안내 |
| 지도 무한 드래그 | 대한민국 영역(lat 33~38.9, lng 124~132) 내에서만 판매점 조회, 범위 이탈 시 조회 중단 |
| 빠른 연속 드래그 | 디바운스 500ms 적용, 마지막 위치 기준으로만 API 호출 |
| 바텀시트 열린 상태에서 다른 마커 클릭 | 기존 바텀시트 즉시 교체, 애니메이션 없이 콘텐츠 변경 |
